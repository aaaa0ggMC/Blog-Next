简介
从暴力枚举到 O(log N) 按位统计：洛谷 P1179 数字统计随想与交互式数位拆解。

内容导读

本文围绕洛谷 P1179（NOIP 2010 普及组）“数字统计”一题展开：给定区间 [L,R][L, R][L,R]，统计所有整数中数字 2 出现的总次数。作者先呈现社区中常见的逐数拆位暴力解法，再重点介绍自己采用的按位统计思路——将”遍历每个数字的每一位”转换为”遍历每一位、统计该位为 2 的数字个数”，从而把复杂度从 O((R−L+1)log⁡10R)O((R-L+1)\log_{10}R)O((R−L+1)log10​R) 降到 O(log⁡10R)O(\log_{10}R)O(log10​R)。文章不仅给出 C++ 与 C 两版实现，还通过具体数值示例、求和顺序交换的推导、三分支公式速查表与复杂度对比，完整交代了算法的正确性来源与工程细节（如统计 0 的前导零特判、大整数溢出规避），并附有 AI 生成的交互式数位拆解演示。

核心要点

  • 问题与朴素解：逐个数拆位、对每位判断是否等于 2 并累加；实现直观，但需对区间内每个数都做一次位数遍历。
  • 按位统计的核心思想：交换计数视角。设 f(N)f(N)f(N) 为 [0,N][0, N][0,N] 中 2 的出现次数，则答案由前缀和相减得到： ans⁡(L,R)=f(R)−f(L−1)\operatorname{ans}(L,R)=f(R)-f(L-1)ans(L,R)=f(R)−f(L−1) 对 NNN 的第 kkk 位（位权 factor=10k\text{factor}=10^kfactor=10k），拆分为高位 high\text{high}high、当前位 cur\text{cur}cur、低位 low\text{low}low 三部分，固定该位为 2 后按 cur\text{cur}cur 与 2 的大小关系分三类累加贡献。
  • 三分支公式：
    • cur<2\text{cur} < 2cur<2：high×factor\text{high} \times \text{factor}high×factor
    • cur=2\text{cur} = 2cur=2：high×factor+low+1\text{high} \times \text{factor} + \text{low} + 1high×factor+low+1
    • cur>2\text{cur} > 2cur>2：(high+1)×factor(\text{high}+1) \times \text{factor}(high+1)×factor
  • 实现优化：C 版本不再反复对 NNN 做除法，而是在迭代中增量维护 high、cur_num、low，减少重复运算。
  • 复杂度对比：暴力法时间 O((R−L+1)log⁡10R)O((R-L+1)\log_{10}R)O((R−L+1)log10​R)、空间 O(1)O(1)O(1)，适用于 R≤107R \le 10^7R≤107 量级；按位统计时间 O(log⁡10R)O(\log_{10}R)O(log10​R)、空间 O(1)O(1)O(1)，可轻松处理 R≤1018R \le 10^{18}R≤1018。
  • 推广与边界：
    • 将判断条件中的 2 替换为任意 d∈[1,9]d \in [1,9]d∈[1,9] 即可复用；
    • 统计数字 0 时需排除前导零：high>0\text{high} > 0high>0 前提下，cur=0\text{cur}=0cur=0 对应 (high−1)×factor+low+1(\text{high}-1)\times\text{factor}+\text{low}+1(high−1)×factor+low+1，cur>0\text{cur}>0cur>0 对应 high×factor\text{high}\times\text{factor}high×factor；
    • 接近 101810^{18}1018 时，factor * cur_num / 10 可能溢出，建议改写为 (factor / 10) * cur_num 并在更新前判断 high > 0。

题目描述

请统计某个给定范围 [L,R][L, R][L,R] 的所有整数中，数字 222 出现的次数。

比如给定范围 [2,22][2, 22][2,22]，数字 222 在数 222 中出现了 111 次，在数 121212 中出现 111 次，在数 202020 中出现 111 次，在数 212121 中出现 111 次，在数 222222 中出现 222 次，所以数字 222 在该范围内一共出现了 666 次。

输入格式

222 个正整数 LLL 和 RRR，之间用一个空格隔开。

输出格式

数字 222 出现的次数。

输入输出样例 #1
输入 #1
2 22
输出 #1
6
输入输出样例 #2
输入 #2
2 100
输出 #2
20
说明/提示

1≤L≤R≤1000001 ≤ L ≤R≤ 1000001≤L≤R≤100000。

NOIP2010 普及组 第一题

常规暴力做法

这题我看社区里大部分人包括题解都是这么做的：

#include <iostream>

int main() {
    std::size_t L,R;
    std::size_t count = 0;

    std::cin >> L >> R;
    for(std::size_t i = L; i <= R; ++i) {
        /// 对 L to R 的每一个数字，遍历其位数找出所有 2
        std::size_t x = i;
        while(x) {
            if(x % 10 == 2) ++count;
            x /= 10;
        }
    
    }
    std::cout << count << std::endl;
}

我的按位统计做法

由于是做练习用因此我第一时间并没有选择用遍历的做法，而是想着去找位数的规律，然后理所应当理解错题目折腾了蛮久，后面看到我以前的做法（可能也是拿 LLM 做的）总算是懂了，这里可以看看算法：

// 20ms 做法
// https://www.luogu.com.cn/problem/P1179
#include <iostream>

std::size_t count_2(std::size_t N) {
    std::size_t count = 0;
    std::size_t factor = 1;
    
    while(N / factor) {
        std::size_t high = N / factor / 10;
        std::size_t cur_num = N / factor % 10;
        std::size_t low = N - N / factor * factor;

        if(cur_num < 2) {
            count += high * factor;
        }else if(cur_num == 2){
            count += high * factor + low + 1;
        }else{
            count += (high+1) * factor;
        }
        
        if(N / 10 < factor) break;
        factor *= 10;
    }
    
    return count;
}

int main() {
    std::size_t N1,N2;
    std::cin >> N1 >> N2;

    std::cout << count_2(N2) - count_2(N1 - 1) << std::endl;
}

原理与随想

没懂？那我就来解释一下吧，首先题目让我们去数有多少个”2”，因此对于任意一个数字，我们都能从其每一位数字数到 0 或者 1 个 2。那么换而言之，我们便可以数当某一位为 2 的时候，这个范围内有多少个数字。这两种计数方式是一致的，这里也可以来证明一下：

倘若从 [0,N] 这个范围数 2 的个数对于 N=aN,mN⋯aN,1aN,0=∑j=0mNaN,j⋅10j其中 mN 表示 N 的位数−1，有：Count=∑i=0N∑j=0mi[ai,j=2]如果令 ai,j=0 当 j>mi 时，可以直接让循环固定从 j=0 遍历到 mN：Count=∑j=0mN∑i=0N[ai,j=2]这样我们只要去操心每一位上满足条件的有多少个数字了\begin{aligned} & \text{倘若从 } [0,N] \text{ 这个范围数 2 的个数} \\ & \text{对于 } N = a_{N,m_N} \cdots a_{N,1} a_{N,0} = \sum_{j=0}^{m_N} a_{N,j} \cdot 10^j \\ & \text{其中 } m_N \text{ 表示 } N \text{ 的位数} - 1\text{，有：} \\ & \text{Count} = \sum_{i = 0}^{N}{\sum_{j = 0}^{m_i}{[a_{i,j} = 2]}} \\ & \text{如果令 } a_{i,j} = 0 \text{ 当 } j > m_i \text{ 时，可以直接让循环固定从 } j = 0 \text{ 遍历到 } m_N\text{：} \\ & \text{Count} = \sum_{j = 0}^{m_N}{\sum_{i = 0}^{N}{[a_{i,j} = 2]}} \\ & \text{这样我们只要去操心每一位上满足条件的有多少个数字了} \end{aligned}​倘若从 [0,N] 这个范围数 2 的个数对于 N=aN,mN​​⋯aN,1​aN,0​=j=0∑mN​​aN,j​⋅10j其中 mN​ 表示 N 的位数−1，有：Count=i=0∑N​j=0∑mi​​[ai,j​=2]如果令 ai,j​=0 当 j>mi​ 时，可以直接让循环固定从 j=0 遍历到 mN​：Count=j=0∑mN​​i=0∑N​[ai,j​=2]这样我们只要去操心每一位上满足条件的有多少个数字了​

我怎么知道？那我们举个例子吧，比如 4613、4623、4633 三个数字，我们怎么数当 10 位数为 2 的时候在 0..46X3 内满足条件的数字个数呢？

先看 4613，固定 10 位数为 2，那么此时为 XX2X，2 把数字分成了高位和低位两个部分。高位上取值能取 46 吗？不能，因为 462X > 4613 恒成立，因此高位只能取 0..45 一共 46 个数字，和高位本身的数值一致。低位呢？低位是一位数，取值 0..9 一共 10 种可能，且如果是 46133，此时低位变成两位数，取值 0..99 一共 100 种可能，刚好是跟随我们的“游标”变化的，因此我们得到了对于 4613，10 位数为 2 时有 high * factor 种可能。factor 为 1, 10, 100… 位数对应低位的位数。

再看 4623，一样的道理，0..45 时和 4613 一样，但是其本身为 2，因此 462X 是存在的，X 刚好可以从 0 到低位数字，一共 low + 1 种可能，加起来便是 high * factor + low + 1。

最后看 4633，固定 10 位数为 2（XX2X），你会发现 high 从 0..46 都可取，low 也可以全部取，4633 必定大于 462X，此时一共 (high + 1) * factor 种可能。

得出这里的分类讨论直接遍历每一位累加就行。这样的时间复杂度是实打实的 O(log N)。当然如果觉得每次迭代这么多计算太麻烦了，可以看看 C 语言版本。因为 high、cur_num、low 实际上已经包含了整个数字的所有信息了，因此迭代的时候调整一下各自就行而不需要拿 N 进行重新运算。
