展开查看：float 精度与“大数吃小数”

C6-1必背核心★重点ECF概念

异常控制流（ECF）概念 & 与子程序调用 CALL 的区别

由于外部中断或内部异常等特殊事件，CPU 打断用户程序正常控制流，转去执行操作系统内核处理程序的控制流称为。与子程序调用 `CALL` 相比：① `CALL` 是程序且有显式转移指令的，而中断/异常多为随机或被动触发、无转移指令；② `CALL` 只保存，而中断响应须同时保存并常伴随用户态→内核态切换。

C6-2必背核心★重点中断与异常

外部中断（异步）vs 内部异常（同步）

（1）：由外部设备通过引脚异步触发，与当前指令无关，CPU 在每条指令执行检测中断引脚，分为可屏蔽中断 ``（如键盘、鼠标、时钟、DMA，受 IF 标志控制）和不可屏蔽中断 ``（如电源掉电、内存校验错，立即响应）。（2）：由当前正在执行的指令直接引发的事件（均由硬件检测并响应）。

C6-5高频考点★重点向量中断

向量中断、实模式向量表 vs 保护模式 IDT

IA-32 采用方式（MIPS 采用软件查询 Cause 寄存器），共 256 种类型号，其中 `` 保留给 CPU 使用（如 0 除法错、2 NMI、14 缺页），32~255 由 OS 自定义（如 Linux 系统调用 `int $0x80`）。实模式下向量表位于物理地址 `0000H~03FFH`（1KB，每项 4B 存 `CS:IP`）；保护模式下使用由 `IDTR` 指向的（2KB，每项 8B），表项分为中断门（TYPE=1110B）、（TYPE=1111B）和任务门，通过门 `DPL` 防止恶意用户态程序模拟 `INT n` 越权陷入内核。

C6-6高频考点★重点Linux信号

Linux 异常处理三阶段 & 0x80000000 / -1 实例

Linux 异常处理程序分为三阶段：① 准备阶段（汇编保存通用寄存器到内核栈）；② 处理阶段（`do_` 前缀的 C 函数向当前进程发信号）；③ 恢复阶段（切回用户态返回断点或信号处理程序）。在 `int a = 0x80000000; int b = -1; int c = a / b;` 中，因使用 `` 除法指令导致商溢出，触发 0 号“除法错”异常 `#DE`，Linux 向进程发送 `` 信号（提示 Floating point exception）；而若直接写 `a / -1`，编译器优化为取负指令 `` 故不触发除法异常。
